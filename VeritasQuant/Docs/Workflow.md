• VeritasQuantDevelopmentWorkflow.md 是一份人、AGENT 和自动化平台共同遵守的协作规程，但三者权限不同。它目前是规范文档，不是能够自行流转任务的工作流程序。

  实际开发流程

  以计划任务 P1-016 为例：

  1. 人员选择任务
     项目负责人确认优先级、负责人、范围和验收标准，并将任务放入当前迭代。

  2. AGENT 检查任务准入
     AGENT 阅读：
      - AGENTS.md
      - VeritasQuantTechSpec.md 对应章节
      - VeritasQuantDevelopmentPlan.md 中的 P1-016
      - VeritasQuantDevelopmentWorkflow.md

     然后检查依赖、验收标准、测试数据和风险是否明确。条件不足时保持 ANALYZING，不能直接开发。

  3. AGENT 执行开发
     AGENT 实现功能、测试、日志、错误码和文档，并记录：
      - 修改文件
      - 测试命令和结果
      - 测试数据及随机种子
      - 产生的风险或未决问题
      - 构建产物和证据哈希

  4. AGENT 提交评审
     完成后只能推进到 IN_REVIEW，不能自行标记 ACCEPTED。独立评审人员或独立评审 AGENT 检查实现是否符合技术方案。

  5. QA 或验收人验证
     根据任务中既定的验收标准执行测试。全部通过并且证据完整后，才能标记为 ACCEPTED。

  6. 自动化系统构建和晋级
     CI 生成不可变 wheel、镜像、测试报告和哈希。SRE 使用同一工件逐环境晋级。

  7. 人员执行 Gate 决策
     阶段负责人根据完整证据给出 PASS、FAIL 或 INSUFFICIENT_EVIDENCE。AGENT可以生成 Gate 报告草稿，但不能代替签署人批准。

  风险与突发问题

  AGENT 在开发中发现问题时，应立即：

  1. 创建或建议创建 RSK-*、BUG-* 或 INC-*。
  2. 记录发现时间、影响范围、关联任务、运行版本和证据。
  3. 对账本不平、未来数据、重复下单、跨账户串扰等问题立即停止相关工作。
  4. 保存日志、trace、配置、数据、测试种子和最小复现样本。
  5. 修复后提供修复前失败、修复后通过的对照证据。
  6. 由人员决定风险接受、里程碑调整或实盘处置。

  当前状态

  目前这份工作流是双用途的规范文档，但尚未实现自动化工作流引擎。AGENT也不会仅因为文件存在就必然主动读取它。要确保后续 AGENT 强制执行，需要：

  - 在 AGENTS.md 中明确要求每个开发任务读取该工作流。
  - 分配任务时提供 PlanTaskId，例如 P1-016。
  - 在 GitHub、GitLab、Jira 等系统中实现对应工作项状态和必填字段。
  - 用 CI 校验任务关联、测试证据、审批和发布 Gate。
  - 为 Risk、Incident、Change 和 StageGateReport 建立机器可读模板。

  推荐的 AGENT 任务指令格式为：

  请按照 VeritasQuantDevelopmentWorkflow.md 执行计划任务 P1-016。
  开始前检查 Definition of Ready；实现后运行验收标准要求的测试，
  登记发现的风险和未决问题，整理证据，但不要自行标记 ACCEPTED 或执行环境晋级。

  因此，准确定位是：人员负责目标、授权和最终责任，AGENT负责受约束的实施与证据生产，自动化系统负责规则执行与状态同步。
